# Zapper — Go + WebView2

Новая версия приложения работает в одном окне и не требует Python, Node.js или Wails. Её можно использовать как планировщик и журнал без подключённой платы либо для управления Arduino Nano через USB.

## Запуск приложения

Запустите `Zapper.exe` из папки portable-версии. Постоянные пользователи и их идентификаторы хранятся в `data/persons.json`, активные профили — в `data/profiles.json`, а каждый запуск имеет отдельный файл в `data/progress/`. Завершённые запуски перемещаются в каталоги `data/archive/<id>/`, содержащие `profile.json` и `progress.json`. Настройки платы хранятся в `data/device.json`, а настройки приложения, включая обнаруженный или выбранный язык, — в `data/settings.json`. Резервные копии остаются в локальных подпапках `backups/`. Всё находится рядом с EXE; ничего не записывается в AppData, Документы или реестр Windows.

В разделе **Профили** можно добавлять людей, создавать готовый текст контекста для AI для копирования в буфер обмена и вставлять упрощённый JSON, возвращённый моделью AI. Частоты в этом формате задаются как `frequency_hz`; приложение проверяет профиль, показывает предварительный просмотр и только после подтверждения создаёт новый `run_id`. Предыдущий активный запуск этого человека сначала переносится в архив.

Во время профильного сеанса кнопка **Пауза** сохраняет оставшуюся часть текущего шага и все следующие шаги в локальном прогрессе. При продолжении в неизменённую прошивку отправляется сокращённая последовательность, после чего снова требуется физическое подтверждение на плате. **Стоп** отменяет частичный прогресс и оставляет весь сеанс доступным для повторного выполнения.

Пропущенные сеансы остаются в очереди как просроченные. Правила программы задают количество частей, перерывы внутри серии, интервал между полными сеансами, время восстановления после сеанса и совместимость с другими программами в тот же день. Профиль без просроченных сеансов автоматически архивируется после завершения плана, а **Завершить программу** позволяет закрыть его раньше.

## Язык приложения

При запуске приложение считывает язык Windows/WebView2 и сопоставляет его с одним из 30 поддерживаемых языков. Пока выбран режим **Автоматически (Windows)**, определение языка выполняется при каждом запуске. Ручной выбор языка в левой панели сохраняется в `data/settings.json` и отключает автоматическую смену до повторного выбора автоматического режима.

Язык приложения также является языком по умолчанию для варианта прошивки. Для систем письма, которые стандартный LCD1602/HD44780 не может надёжно отображать, приложение выбирает соответствующий вариант прошивки с английским текстом на LCD; настольный интерфейс при этом продолжает использовать выбранный язык.

## Arduino и USB

Текущая прошивка находится в `firmware/zapper_v5/zapper_v5.ino`, а её описание — в `firmware/zapper_v5/README.md`. После загрузки прошивки:

1. Откройте раздел **Устройство**.
2. Выберите COM-порт и нажмите **Подключить**.
3. Дождитесь состояния **Готово**.
4. Отправьте сегодняшний сеанс или запустите одно значение в ручном режиме.
5. Проверьте подключения на плате, затем нажмите физическую кнопку; выход включится только после этого.

Выбранный порт сохраняется в локальном файле `data/device.json`. Профильные сеансы хранят отдельные точные `device_steps`; описание вроде «30 kHz» остаётся текстом для человека, а плата получает `30000000` миллигерц и длительность в миллисекундах.

### Языки LCD-прошивки

Прошивка 5.1.0 имеет 30 отдельных языковых вариантов, создаваемых из одной кодовой базы. Каждый Arduino sketch содержит только один набор текстов LCD. Языки на латинице имеют собственные короткие строки, сохранённые в безопасном ASCII. Для кириллицы и других систем письма, которые обычный LCD1602/HD44780 не может надёжно отображать, соответствующий вариант использует английский интерфейс LCD. Полный список находится в `firmware/LANGUAGES.md`.

Команда `go run ./tools/firmware_i18n` создаёт все sketch-файлы в `build/generated/firmware/`. Обычный процесс `build.ps1` делает это автоматически и включает варианты в portable-версию.

### Загрузка прошивки из приложения

Раздел **Устройство → Firmware** показывает обнаруженную версию, последнюю версию, язык варианта прошивки и язык LCD. Пользователь выбирает новый или старый загрузчик Arduino Nano и явно нажимает **Загрузить прошивку**; приложение никогда не записывает прошивку на плату автоматически при запуске.

Компиляцию и загрузку выполняет `arduino-cli`. Zapper ищет его в `tools/arduino-cli/`, рядом с EXE, в `PATH` и в типичных каталогах Arduino IDE. Если инструмент отсутствует, приложение прямо сообщает об этом, а кнопка загрузки остаётся недоступной. Для компиляции также необходимы core `arduino:avr` и библиотека `LiquidCrystal_I2C`, доступные для используемой установки `arduino-cli`.

### Определение языка и выбор прошивки

При запуске приложение считывает язык среды WebView2/Windows (`navigator.languages`) и сопоставляет его с одним из 30 поддерживаемых кодов. Если язык системы не поддерживается, выбирается английский. В режиме **Автоматически (Windows)** язык проверяется при каждом запуске; ручной выбор сохраняется в `data/settings.json` до повторного включения автоматического режима.

Тот же код языка используется как выбор по умолчанию на экране загрузки прошивки. Для языков, которые LCD1602 не поддерживает, приложение всё равно выбирает вариант, помеченный языком пользователя, но сообщает, что текст LCD будет английским. Прошивка никогда не загружается автоматически при запуске приложения; загрузка требует явного клика пользователя, чтобы случайно не перезаписать другую программу, уже находящуюся на Arduino.

## Сборка

Требуется Go. Проще всего запустить в корневой папке проекта:

```text
build.bat
```

Либо в PowerShell:

```powershell
.\build.ps1
```

Скрипт выполняет тесты и анализ кода, собирает `build/generated/Zapper-dev.exe` и подготавливает portable `build/Zapper/Zapper.exe` без окна консоли.

## Структура проекта

- `app/` — код Go, интерфейс HTML/CSS/JS, руководство и база частот.
- `firmware/zapper_v5/` — текущая прошивка Arduino.
- `data/` — активные профили, прогресс, архив, настройки устройства и автоматические резервные копии.
- `locales/` — версионируемые переводы интерфейса и инструкции, используемые при разработке и копируемые в релизы.
- `build/Zapper/` — готовая portable-версия для копирования на другой компьютер.
