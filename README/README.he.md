# Zapper — Go + WebView2

הגרסה החדשה של היישום פועלת בחלון יחיד ואינה דורשת Python, Node.js או Wails. אפשר להשתמש בה כמתכנן וכיומן ללא לוח מחובר, או לשלוט ב-Arduino Nano דרך USB.

## רישיון ואחריות

הקוד, ה-firmware, התרשימים והתיעוד זמינים לציבור לשימוש לא מסחרי תחת רישיון **PolyForm Noncommercial 1.0.0**. מותר להשתמש בהם, ללמוד אותם, לשנות ולהפיץ אותם למטרות שהרישיון מתיר, אך אין להשתמש בפרויקט באופן מסחרי ללא אישור נפרד מהמחבר. לפרטים ראו את הקובץ `LICENSE`.

הפרויקט מסופק ללא אחריות לצורך ניסויים עצמאיים ושימושי DIY. המשתמש אחראי להרכבה נכונה, לשינויים ולאופן השימוש במכשיר. המחבר אינו אחראי לנזק לחומרה, לנזקים אחרים או לתוצאות של הרכבה או שימוש שגויים, ואינו מבטיח השפעות בריאותיות מסוימות.

## הפעלת היישום

הפעילו את `Zapper.exe` מתוך תיקיית הגרסה הניידת. אנשים קבועים והמזהים שלהם נשמרים ב-`data/persons.json`, פרופילים פעילים ב-`data/profiles.json`, ולכל הרצה יש קובץ נפרד ב-`data/progress/`. הרצות שהושלמו מועברות לתיקיות `data/archive/<id>/` שמכילות `profile.json` ו-`progress.json`. הגדרות הלוח נשמרות ב-`data/device.json`, והגדרות היישום, כולל השפה שזוהתה או נבחרה, נשמרות ב-`data/settings.json`. גיבויים נשארים בתיקיות המשנה המקומיות `backups/`. הכול נמצא ליד קובץ ה-EXE; שום דבר אינו נכתב ל-AppData, למסמכים או לרישום של Windows.

בתצוגת **פרופילים** אפשר להוסיף אנשים, ליצור טקסט הקשר מוכן ל-AI להעתקה ללוח ולדביק JSON פשוט שהוחזר על ידי מודל AI. תדרים בפורמט הזה ניתנים באמצעות `frequency_hz`; היישום מאמת את הפרופיל, מציג תצוגה מקדימה ויוצר `run_id` חדש רק לאחר אישור. ההרצה הפעילה הקודמת של אותו אדם מועברת קודם לארכיון.

במהלך הפעלת פרופיל, הכפתור **השהה** שומר את החלק שנותר מהשלב הנוכחי ואת כל השלבים שאחריו בהתקדמות המקומית. המשך ההפעלה שולח רצף מקוצר ל-firmware שלא השתנה ודורש שוב אישור פיזי על הלוח. **עצור** מבטל את ההתקדמות החלקית ומשאיר את כל ההפעלה זמינה לביצוע מחדש.

הפעלות שדולגו נשארות בתור כמאחרות. כללי התוכנית מגדירים את מספר החלקים, הפסקות בתוך סדרה, מרווח בין הפעלות מלאות, זמן התאוששות לאחר הפעלה ותאימות לתוכניות אחרות באותו יום. פרופיל ללא הפעלות מאחרות מועבר אוטומטית לארכיון עם השלמת התוכנית, ואילו **סיים תוכנית** מאפשר לסגור אותו מוקדם יותר.

## שפת היישום

בעת ההפעלה, היישום קורא את שפת Windows/WebView2 ומתאים אותה לאחת מ-30 השפות הנתמכות. כל עוד ההגדרה נשארת במצב **אוטומטי (Windows)**, זיהוי השפה מתבצע בכל הפעלה. בחירת שפה ידנית בלוח השמאלי נשמרת ב-`data/settings.json` ומבטלת שינויים אוטומטיים עד לבחירת המצב האוטומטי מחדש.

שפת היישום היא גם שפת ברירת המחדל של גרסת ה-firmware. עבור מערכות כתיבה ש-LCD1602/HD44780 רגיל אינו יכול להציג באופן אמין, היישום בוחר את גרסת ה-firmware המתאימה עם טקסט LCD באנגלית; ממשק שולחן העבודה ממשיך להשתמש בשפה שנבחרה.

## Arduino ו-USB

ה-firmware הנוכחי נמצא ב-`firmware/zapper_v5/zapper_v5.ino`, והתיאור שלו נמצא ב-`firmware/zapper_v5/README.md`. לאחר טעינת ה-firmware:

1. פתחו את תצוגת **התקן**.
2. בחרו יציאת COM ולחצו על **התחבר**.
3. המתינו למצב **מוכן**.
4. שלחו את ההפעלה של היום או הפעילו ערך יחיד במצב ידני.
5. בדקו את החיבורים על הלוח ולאחר מכן לחצו על הכפתור הפיזי; רק אז הפלט יתחיל.

היציאה שנבחרה נשמרת בקובץ המקומי `data/device.json`. הפעלות פרופיל שומרות `device_steps` נפרדים ומדויקים; תיאור כמו “30 kHz” נשאר טקסט קריא לאדם, בעוד שהלוח מקבל `30000000` מיליהרץ ואת משך הזמן במילישניות.

### שפות firmware למסך LCD

ל-firmware 5.1.0 יש 30 גרסאות שפה נפרדות שנבנות מבסיס קוד אחד. כל Arduino sketch מכיל רק ערכת טקסטים אחת ל-LCD. לשפות שמשתמשות באלפבית לטיני יש טקסטים קצרים משלהן השמורים כ-ASCII בטוח. עבור קירילית ומערכות כתיבה אחרות ש-LCD1602/HD44780 טיפוסי אינו יכול להציג באופן אמין, הגרסה המתאימה משתמשת בממשק LCD באנגלית. הרשימה המלאה נמצאת ב-`firmware/LANGUAGES.md`.

הפקודה `go run ./tools/firmware_i18n` יוצרת את כל קובצי ה-sketch בתוך `build/generated/firmware/`. תהליך `build.ps1` הרגיל מבצע זאת אוטומטית ומצרף את הגרסאות לחבילת ה-portable.

### טעינת firmware מתוך היישום

החלק **התקן → Firmware** מציג את הגרסה שזוהתה, הגרסה העדכנית ביותר, שפת גרסת ה-firmware ושפת ה-LCD. המשתמש בוחר bootloader חדש או ישן של Arduino Nano ולוחץ במפורש על **טען firmware**; היישום לעולם אינו כותב firmware ללוח באופן אוטומטי בעת ההפעלה.

הקומפילציה וההעלאה מתבצעות באמצעות `arduino-cli`. Zapper מחפש אותו ב-`tools/arduino-cli/`, לצד קובץ ה-EXE, ב-`PATH` ובמיקומים רגילים של Arduino IDE. אם הכלי אינו זמין, היישום מציג זאת בבירור וכפתור ההעלאה נשאר מושבת. הקומפילציה דורשת גם את core `arduino:avr` ואת הספרייה `LiquidCrystal_I2C` זמינים להתקנת `arduino-cli` שבה משתמשים.

### זיהוי שפה ובחירת firmware

בעת ההפעלה, היישום קורא את שפת סביבת WebView2/Windows (`navigator.languages`) ומתאים אותה לאחד מ-30 הקודים הנתמכים. אם שפת המערכת אינה נתמכת, נבחרת אנגלית. במצב **אוטומטי (Windows)** השפה נבדקת בכל הפעלה; בחירה ידנית נשמרת ב-`data/settings.json` עד להפעלה מחדש של המצב האוטומטי.

אותו קוד שפה הוא ברירת המחדל במסך טעינת ה-firmware. עבור שפות שאינן נתמכות על ידי LCD1602, היישום עדיין בוחר את הגרסה שמסומנת בשפת המשתמש, אך מציין שטקסט ה-LCD יהיה באנגלית. ה-firmware לעולם אינו נטען אוטומטית בעת הפעלת היישום; הטעינה דורשת לחיצה מפורשת של המשתמש כדי שלא לדרוס בטעות תוכנית אחרת שכבר שמורה ב-Arduino.

## בנייה

נדרש Go. הדרך הפשוטה ביותר היא להריץ בתיקיית השורש של הפרויקט:

```text
build.bat
```

או ב-PowerShell:

```powershell
.\build.ps1
```

הסקריפט מריץ בדיקות וניתוח קוד, בונה את `build/generated/Zapper-dev.exe` ומכין את גרסת ה-portable `build/Zapper/Zapper.exe` ללא חלון קונסולה.

## מבנה הפרויקט

- `app/` — קוד Go, ממשק HTML/CSS/JS, מדריך ומסד נתוני תדרים.
- `firmware/zapper_v5/` — firmware Arduino הנוכחי.
- `data/` — פרופילים פעילים, התקדמות, ארכיון, הגדרות מכשיר וגיבויים אוטומטיים.
- `locales/` — תרגומי ממשק ומדריך הנשמרים בבקרת גרסאות, משמשים בפיתוח ומועתקים למהדורות.
- `build/Zapper/` — גרסת portable מוכנה להעתקה למחשב אחר.
